# honua-gp compatibility matrix

> **Native application path:** [gRPC for live data and edits; PMTiles, GeoParquet and COG through the CDN](../native-data-paths.md). Start there for browser gRPC-Web setup, signed private URLs and regeneration after changes. OGC API and GeoServices REST examples below are compatibility workflows.

Generated from the in-code ``COMPAT`` manifest by ``scripts/render_compat_matrix.py`` (re-run after manifest edits).

Statuses: **Supported** runs against Honua, **Partial** runs with documented deviations, **Stub** raises ``HonuaGpUnsupportedError`` with a replacement hint and tracking ticket.

## analysis.*

| <a id="analysisbuffer"></a>`analysis.Buffer` | Partial | `process` | Projects analysis.Buffer onto honua-server's layer-aware analytics.buffer-aggregate process: in_features -> layerId, the linear distance is split into distance+unit, and dissolve_option NONE/ALL maps to dissolve=false/true. Runs as an async OGC API Processes job (submit + poll). Deviation: the scripting API's per-feature FULL/LIST buffer side table is not modelled; dissolve is all-or-nothing plus optional groupByFields. line_side, line_end_type, and method are validated against their scripting-API defaults (FULL/ROUND/PLANAR) and rejected with HonuaGpConfigurationError otherwise -- never silently ignored.
